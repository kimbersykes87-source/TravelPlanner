## What changed in the app

### Visa and residency numbers

- Every table loads in pages of 1,000 rows. The daily log had silently stopped
  at 26 June 2026 (Supabase's default page size). The Past relationship
  timeline and all visa tiles now see the full log.
- One visa engine in `src/lib/visa/` is used by the Us tab and the Scenario
  Visa Check, so they cannot drift.
- Country matching is exact names and ISO codes, not substring checks (so
  "Australia" no longer counts as the US, "Ukraine" no longer counts as the UK).
- Schengen includes Bulgaria and Romania (members since 1 January 2025).
- US territories (Puerto Rico and others) count as the US. The ESTA clock
  keeps running through Canada, Mexico and the Caribbean.
- Us tab tiles show days left, day X of 90 with a must-leave-by date, last
  and next US stay, planned breaches, UK days used vs planned, and work-tie
  status.
- Passport labels: both British; Kimber's second is Australian. Siona's US
  visa is shown.
- 21 unit tests (`npm test`).

### Data loading

- `TravelDataProvider` loads all tables once and shares them across tabs.
  Switching tabs no longer re-downloads everything. Saves refresh in the
  background.

### Google Sheets sync

- New `apps-script/SyncToSupabase.gs` (pasted over the old file; `00-ALL-TABS.gs`
  and `02-PAST-TAB.gs` were left alone).
- Checks the Sheet before sending: duplicate or missing dates, unknown country
  names, swapped expiry dates.
- Upserts in batches, then removes Supabase rows that are no longer in the
  Sheet (refuses to delete more than a quarter of a table in one go).
- Writes a row to `sync_runs`. The Us tab shows "Synced from Google Sheets
  … ago" (amber after 48 hours, red on failure) and any data warnings.
- Dates are read in the Sheet's time zone.
- Menu: **Sync to Supabase** and **Check data only (no sync)**.
- Writes with the **service role** key (`SUPABASE_SERVICE_ROLE_KEY` in Apps
  Script properties). The old anon key no longer works now the database is
  locked.
- Dead mappings removed: PreRelationshipCountries, PresentBookings, BucketList
  (bucket list is app-only). Two empty tables were dropped
  (`pre_relationship_countries`, `present_bookings`).

### Sign-in and lock-down

- Shared site password (`PasswordGate` / `VITE_APP_PASSWORD`) is gone.
- Email + password via Supabase Auth. Two accounts (Kimber and Siona). New
  sign-ups are turned off. Each phone stays signed in.
- Row Level Security: only rows in `app_members` can read; those members can
  write the app-edited tables. Sheet-owned tables are written only by the
  sync (service role). Guests get nothing.
- `/view?k=<token>` share links go through the `viewer-data` Edge Function.
  Viewers never query the database. Passports, visas, dates of birth,
  frequent-flyer numbers and UK work-day flags are not sent. Create / replace
  the link on the Us tab.

### Polish

- One country / flag / continent library (`src/lib/countries/`) replaces three
  hand-typed copies.
- ESLint clean. Keyboard focus ring and labelled login fields.
- Docs rewritten for v2 (ARCHITECTURE, GOOGLE_SETUP, AUTH_SETUP, VISA_RULES,
  VIEWER_MODE, README). Deploy now runs tests, lint and build, then
  `--force-with-lease`.

## Problems we hit (keep these)

### Windows file-name collision (build)

`ViewerContext.jsx` and `viewerContext.js` (same names, different case) live
in the same folder. Windows treats them as one file, so Vite imported the
wrong one and the production build failed (`ViewerProvider is not exported`).
The same trap existed for Auth.

**Fix that shipped:** the `.js` context files were replaced by
`auth-context.js`, `viewer-context.js` and `travel-data-context.js`. Do not
add two files in the same folder that differ only by case.

### Signed-in users could not see data before the lock

The old RLS policies were `TO anon` only. After sign-in, every request uses
the `authenticated` role, so Postgres returned empty lists and no error. The
Us tab said "No profiles yet". The 404 in the console was `sync_runs` (that
table did not exist until step 6) and was harmless.

The rollout notes had assumed "database still open, so signed-in users see
everything". That was wrong. The open policies never covered signed-in users.

**Fix that shipped:** we went on to the lock-down and added the two members
straight away. Do not rely on "open to anon" to test a signed-in app.

### Supabase CLI was on the wrong account

`npx supabase login` in the agent shell cannot open a browser (non-TTY). The
CLI was already logged into a different org (RA Portal / gap-year planner),
so `functions deploy` returned 403 until login was run in a normal Cursor
terminal with the Travel Planner account.

Use: `cd c:\dev\TravelPlanner_v2` then `npx supabase login`, then
`--project-ref xaxbbtzsyrtchtjrjvqy`. Deploy functions with `--use-api` if
Docker is not available.

### Security Advisor warnings that are not a problem

After lock-down, Advisors > Security showed two warnings, neither of which
is "RLS off" or "anon can read":

- **`public.is_member()` SECURITY DEFINER:** expected. That function is how
  policies ask "is this signed-in person a member?" Guests cannot call it.
  Leave it.
- **Leaked password protection disabled:** optional extra in
  Authentication > Attack Protection. Not part of the lock-down.

The temporary-reopen recipe in AUTH_SETUP must use `TO authenticated` if the
people who need access are signed in, not only `TO anon`.
